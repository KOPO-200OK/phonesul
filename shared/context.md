# shared/context.md — ③ 앱별 컨텍스트: 건강폰술

> 3-파일 구조 중 셋째. 건강폰술 전용 결정을 담는다. 다른 아이디어로 갈 땐 이 파일을 통째로 새로 쓴다.
>
> `shared/`는 여러 AI agent adapter가 공통으로 읽는 벤더 중립 스펙이다.
> 여기서 말하는 "공유"는 앱/플랫폼이 고정된다는 뜻이 아니라,
> 실행 agent가 바뀌어도 동일하게 주입되는 계약 입력이라는 뜻이다.

## 0. 앱 정체성

- 이름(가칭): **건강폰술**
- 정의: 실제 음주 없이 폰으로 술을 따르고 건배하는 절주·대체형 소셜 WebApp.
- 타깃: 비음주자, 절주·금주 중인 사람.
- 톤: 가볍고 유쾌하게. 음주 미화·과음 조장 금지.

> 콘셉트: "마시는 앱"이 아니라 "안 마시는 사람을 위한 앱". 모든 기능·문구가 이 프레임을 따른다.

## 1. 핵심 기능

| # | 기능 | 동작 |
|---|---|---|
| 1 | 음료 선택 | 5종(소주·맥주·와인·막걸리·샴페인). 종류별 병·잔·색·소리·점도 차등 |
| 2 | 길게 눌러 따르기 | 길게 누르면 잔 차오름 + 종류별 사운드·햅틱 |
| 3 | 탭해서 비우기 | 탭하면 잔이 비워지는 가상 애니메이션 |
| 4 | 샴페인 흔들기 축하 | 샴페인 한정. 흔들면 코르크 펑 + 거품 분출 |
| 5 | 상황 모드 | 혼술 / 술자리 분기 |
| 6 | 실시간 건배방 (F-RT) | 방 생성·코드 공유·참여·인원 동기화·실시간 짠·종료/만료. 별도 백엔드(FastAPI+wss) 연동 |

- SDK 사용법은 여기 적지 않는다 → adapter별 SDK 지식 도구(MCP/문서/스킬 폴백)에 위임.
- **기록 기능(누적 잔 수·절약 칼로리·비용)은 v0.2에서 제거됨** — "기록·점수·보상 없이 동작·분위기 자체로 만족"(기능정의서 v0.4 §1.3).
- **비동기 공유 링크 건배(구 F-CH)는 v0.3에서 제거됨** — 실시간 건배방(F-RT)으로 대체. 더는 "링크 보내면 상대가 열어 짠" 경로 없음(기능정의서 v0.4 §2.1·§4.C·§12).
- **술자리 모드 '원샷' 문구는 v0.4에서 정리됨** — "활기찬 분위기·경쾌한 템포"로 대체(음주 조장 완화). §5.1 문구 가이드의 "원샷!" 금지와 정합.

> 기능정의서 v0.4 F-CR/MD/RT/SY와 정렬. 실시간 건배방 상세·서버 규약은 정본 [폰술_기능정의서_v0.4.md](../docs/spec/폰술_기능정의서_v0.4.md) §4.C·§10, 검수 필수(F-SY)는 §7·§10.

## 2. 화면 흐름

```
진입 → 모드 선택 → 음료 선택 → 길게 눌러 따르기 → 탭해서 비우기 → (반복)
                              └ 샴페인 → 흔들어 축하 → 복귀
       건배(S-06) → 건배방 만들기 / 코드로 참여 → 실시간 건배방(S-10) → 전원 동시 짠
```

- 따르기·비우기는 한 화면에서 대기→따르기→비우기 상태 순환(무한 반복).
- 실시간 건배방(S-10): 방 코드·인원 목록·짠 버튼·연결 상태 표시. 누구나 짠 → 방 전원 동시 연출.
- 화면 상세는 화면설계서에서 확정. v0.3 화면설계서는 S-06/S-07 링크 제거·S-10 신규 반영.

## 3. 데이터 구조

- 프론트는 클라이언트 Storage만 사용(영속 DB 없음). 실시간 건배방 상태는 별도 백엔드 서버 메모리(in-memory)에만 두며 방 종료 시 폐기.

| 항목 | 저장 | 설명 |
|---|---|---|
| 선택 술 종류 | 세션 | 현재 선택 술(5종) |
| 화면 상태 | 세션 | 대기/따르기/마시기 + 잔 차오름 0~100% |
| 설정값 | 로컬 영구 | 사운드·햅틱 on/off |
| 모드 | 로컬 영구 | 마지막 선택 모드 |
| 방(Room) | 서버 메모리(휘발) | 코드·방장 토큰·멤버 목록·시각. 방 종료 시 폐기, 코드 재사용 금지 |
| 멤버(Member) | 서버 메모리(휘발) | 서버 발급 익명 식별자(memberId·socketId). 실명·연락처·토스 식별값 미저장 |

- v0.2: 누적 잔 수·절약 환산(F-HL) 제거 — 영속 누적 데이터 없음.
- v0.3: 비동기 공유 링크 식별값 제거 — 건배는 실시간 방 코드(서버 발급·휘발)로만 동작.

## 4. 기술 구현

- WebView (React 18 + Vite). React Native 금지.
- 프론트는 정적/CSR(자체 백엔드 없음). 실시간 건배방만 별도 백엔드(FastAPI + WebSocket, 별도 레포·배포)에 연결.
- 사용 SDK: Storage, share, getTossShareLink(방 코드 공유 F-RT-02), getAnonymousKey, generateHapticFeedback.
- 실시간 건배방: REST(방 생성/종료) + wss(참여·인원·짠). 서버 주소는 env 주입(하드코딩 금지). → `// REVIEW(서버 endpoint 설정):` / `// UNVERIFIED:` 토스 WebView에서 wss(교차 Origin) 연결 허용 여부 실기기 검증.
- Lottie는 `lottie-web` 사용(RN SDK 금지).
- 오디오 백그라운드는 `visibilitychange`로 정지/재개. → `// REVIEW:` 포그라운드 복귀 BGM 동작 확인. 백그라운드 전환 시 소켓·사운드 동시 처리(F-SY-04 연계). → `// REVIEW(백그라운드 소켓 처리):`

> 백그라운드 복귀 시 BGM 미재생은 과거 반려 사례. 반드시 처리.

### 4.1 모션 센서 — 검증 필요

- 따르기 기본 = 길게 누르기(센서 무관, 폴백 보장).
- 기울여 따르기 = `DeviceOrientationEvent`(검증 성공 시 추가).
- 샴페인 흔들기 = `DeviceMotionEvent`(셰이크, 임계값·쿨다운).

> 모션은 SDK 아닌 웹 표준 API. iOS는 `requestPermission()` 필요(탭 제스처 내 호출), 기기별 편차 있음.

- 검증 항목(현승, 화요일 구현 시) → 모두 `// UNVERIFIED:`
  - WebView에서 `deviceorientation` 값 수신 여부
  - iOS `DeviceMotion.requestPermission()` 토스 WebView 동작 여부
  - `devicemotion` 흔들기 감지 안정성
- 센서 실패 시: 따르기는 길게 누르기 유지, 샴페인은 대체 트리거 폴백.

## 5. 음주 콘텐츠 UX·문구 대응

> ②§4(2단계 분류 가능성)에 대한 구체 대응.

- 음주 미화·권장 금지. 대체·절제 맥락을 UX·문구에서 분명히.
- 음주 유도 표현·과음 연출·술 권하는 톤 금지.
- 술 브랜드 실명 금지.
- 절제 메시지는 기록·수치가 아니라 동작·분위기 자체와 슬로건("마시지 않고, 분위기만")으로 전달(v0.2: 기록 기능 제거).
- 민감 콘텐츠 분류 시 진입 전 동의 화면과 콘셉트(대체·절제) 정합성 확인.

> 문구·연출은 사용자 노출이라 AI 흔적·UX 자연성 검수 대상(①§7). → `// REVIEW:`

### 5.1 문구 가이드 (금지 → 대체)

| 금지 | 대체 |
|---|---|
| 한 잔 더 마셔볼까요? | 한 번 더 가상 건배해볼까요? |
| 원샷! | 가볍게 비워볼까요? |
| 취할수록 재밌어요 | 실제 음주 없이 분위기만 즐겨요 |
| 술이 부족해요 | 다른 조합도 둘러볼까요? |
| 오늘 제대로 마셔요 | 오늘은 마시지 않고 분위기만 즐겨요 |

> UI 문구 생성 시 이 표를 기준으로. 음주 권장 톤·AI 문구 실수 동시 차단.

## 6. 비게임 유지

> 분류 리스크 근거는 ②§7. 여기선 구체 배제 결정.

- 점수·랭킹·레벨·리더보드 배제 (게임 분류 시 GRAC 의무 발생).
- 실시간 짠은 경쟁·순위 아닌 동시 축하로 설계 — **누가 먼저/많이 짠 표시·집계·순위 금지**(구조적으로 sender·count 미포함). 방은 경쟁이 아니라 함께 축하.
- 샴페인 흔들기는 축하 연출이지 게임 메커닉 아님(점수·성공/실패·목표 없는 1회성). 따르기·비우기도 목표·엔딩 없는 무한 반복.

## 7. 검수 필수 기능 · 비기능 요구사항

> 기능정의서 F-SY·비기능 반영. 앱인토스 검수 통과 필수.

### 7.1 검수 필수 기능 (F-SY)
- 사운드 On/Off(F-SY-01), 진동 On/Off(F-SY-02). 설정 재진입 후 유지. 진동 꺼도 시청각 피드백 유지(접근성: 단일 감각 의존 금지).
- 무음 모드 존중(F-SY-03). 무음 시 사운드 자동 억제. 시스템 자동 동작.
- 백그라운드 사운드 제어(F-SY-04). 백그라운드 시 즉시 정지, 복귀 시 재생. `visibilitychange`(§4). 시스템 자동 동작.
- 종료 확인 모달(F-SY-05). 실수 종료 방지.
- 닫기 버튼(F-SY-06). 우측 상단 X, 모든 주요 화면에서 동작.

### 7.2 성능
- 초기 로딩 10초 이내(F-SY-07). 미달 시 검수 탈락.
- 인터랙션 반응 2초 이내(F-SY-08). 에셋 사전 로드. 미달 시 검수 탈락.

### 7.3 인터랙션 디테일
- 헛누름 분기(F-CR-04): 손 떼는 시점 잔 수위 < 임계값(예 8%)이면 비우기 안 가고 대기 복귀. → `// ASSUMPTION:` 8%는 임의값.
- 상태 순환: 한 라우트에서 요소 등장/퇴장(페이드)으로 끊김 최소화.
- 안정성: 상태 전환 반복 시 메모리·사운드 누수 없이 동작.

### 7.4 실시간 건배방(F-RT) 추가 고려
- 실시간 짠 연출의 사운드·진동은 설정·무음 모드 종속(F-SY-01/02/03 승계). 진동 꺼도 시각 피드백 유지.
- wss 연결 끊김/실패 시 사용자 안내(에러 상태) — 음주 조장 톤 없는 문구. 끊김 시 재연결(F-RT-07) 동선.
- 익명·휘발: 프론트는 개인정보 입력 없이 코드로만 참여. 코드 추측 남용 방지(시도 제한).
- 실시간 짠 체감 지연 최소화(수백 ms 목표). 연타는 서버 쿨다운과 정합. → `// REVIEW(실측):`

## 9. 자산 (미정·후보)

> 자산 필요 여부 자체가 일부 미정. 단계가 요구하면 쓰고 아니면 줄인다(①).

- 일러스트: 현주 선별 1차 + 부족분만 이미지 AI 보강. 5종 스타일 일관성 검수. → `// REVIEW:`
- 사운드: 효과음 필요 여부 **팀 미정**. 생성 시 ElevenLabs SFX 또는 CC0 후보. 적용 전 플랜·상업 사용·앱 내 사용 범위·독립 배포 제한 확인. → `// UNVERIFIED:`
- 정적 자산에 생성형 AI 고지 의무(②§3) 적용되는지 확인. → `// UNVERIFIED:`
