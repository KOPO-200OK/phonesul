# shared/platform.md — ② 앱인토스 플랫폼 규칙 (Platform Rules)

> **이 파일의 위치**: 여러 agent adapter가 공통으로 읽는 `shared/` 구조 중 두 번째.
> ① 파이프라인 방법론 · ② 앱인토스 플랫폼 규칙(이 파일) · ③ 앱별 컨텍스트
>
> **이 파일은 앱인토스라는 특정 플랫폼에 종속된 규칙을 담는다.** 플랫폼이 바뀌면 이 파일만 교체하고 ①은 유지한다.
>
> **기준 시점: 2026-06-21.** 앱인토스 심사 기준은 고정되어 있지 않고 수시로 개정되며, 공식 문서에 없던 항목이 반려 후 추가되는 사례가 보고된다. 따라서 이 파일의 규칙은 "이 시점의 공식 문서 기준"이며, 출시 직전 공식 문서로 재확인한다. (출처: developers-apps-in-toss.toss.im)

---

## 0. 역할 분담 — 이 파일이 다루지 않는 것

**SDK 사용법(how)과 agent별 설치 커맨드는 이 파일에 적지 않는다.** 함수 시그니처·API 구조·빌드·배포·TDS 적용은 adapter별 tool config와 앱인토스가 제공하는 도구에 위임한다:

- **MCP (ax 툴킷)**: SDK 문서·코드 예제·프로젝트 생성·빌드·배포 워크플로우 보조. 연결 방식은 agent adapter별로 관리한다.
- **문서/스킬 폴백**: 공식 문서 키워드·의미 검색은 adapter별 지원 방식에 맞춘다.
- **프로젝트 생성 시 agent 선택값**: 전환 시점의 앱인토스·agent 제품 문서로 재확인한다.

> **이 파일이 다루는 것은 도구가 모르는 "정책 판단(what)"이다.** MCP는 "share 함수를 이렇게 쓴다"는 알려줘도 "이 앱의 이 기능이 정책에 걸린다"는 판단하지 못한다. 그 판단을 여기에 가드레일로 박는다.

## 1. 출시 불가 — 절대 금지 (어기면 등록 자체가 안 됨)

아래에 해당하면 출시가 불가하다. 구현 전에 걸러야 한다.
(출처: 서비스 오픈 정책 /intro/guide.md)

- **디지털·가상자산**: 소유·이전·거래·발행(NFT 포함) 기능
- **자금세탁 가능 구조**: 현금/유사자산의 직접 교환·전환·환불 기능
- **불법·부정행위 조장**: 신분 조작, 해킹, 불법 문서, 정보수집 우회
- **사행성·복권·베팅성 콘텐츠**
- **금융상품 중개·판매·광고**: 대출·보험·카드·증권
- **투자자문·리딩방·유료 정보제공**
- **의료**: 비대면 진료, 병원 예약, 병원 광고비 수취 구조
- **단순 홍보 목적**: 기존 회사/서비스를 단순 홍보하려고 미니앱을 내는 것

> 내부 정책상 법 위반이 아니어도 브랜드·UX·리스크 관리 차원에서 반려될 수 있다. 사전 등록을 보장하지 않는다.

## 2. 연결·연동 제한 (로그인·결제·광고·외부링크)

(출처: /intro/guide.md §4, §6)

- **로그인**: 토스 로그인만 가능. 소셜·간편 로그인 불가.
- **결제(실물)**: 토스페이만. PG사 포함 기타 수단 불가.
- **결제(디지털)**: 인앱결제만.
- **광고**: 앱인토스 전면형·보상형·배너만. 외부 광고 네트워크 불가.
- **자사 앱 설치 유도 금지**: "앱 설치하면 더 많은 기능" 류 문구·배너·마켓링크 일체 불가.
- **외부 링크 제한**: 핵심 기능이 외부 링크에 의존하면 안 됨. 공유 링크가 자사 웹사이트로 랜딩되면 안 됨. 미니앱 안에서 기능이 완결되어야 함.

## 3. 생성형 AI 결과물 — 고지·표시 의무

(출처: /intro/guide.md §5)

AI가 생성한 텍스트·이미지·음성·영상을 사용자에게 노출하는 경우, 공식 문서 기준의 고지·표시 의무를 확인한다:

- **사전 고지**: 최초 이용 시 "이 기능은 생성형 AI를 활용함"을 사용자가 인지하도록 고지
- **표시 의무**: AI 생성 결과물임을 사람이 즉시 인식하도록 표시 (라벨·배지·워터마크 등)
- **위반 시**: 과태료·자료 제출·현장조사·서비스 중지 등 제재 가능성이 있으므로 출시 전 확인한다.

> **적용 범위 주의**: 실시간 생성 결과물과 사전 제작 정적 자산(미리 만든 효과음·그림)은 의무 적용 범위가 다를 수 있다. 출시 전 공식 문서와 채널톡 문의로 확인한다. → `// UNVERIFIED:` 표시 대상.

## 4. 민감 콘텐츠 기준 — 음주 묘사

(출처: 서비스별 주의사항 /intro/caution.html, 민감 콘텐츠 등급 기준표)

민감 콘텐츠 "약물·도박" 항목 기준:

| 단계 | 기준 |
|---|---|
| 1단계 (경미) | 배경에 등장 / 실제 섭취 아님 |
| 2단계 (주의) | 음주 장면 반복 / 도박 행위 등장 |
| 3단계 (출시 불가) | 마약 사용·판매 / 도박 미화·권장 |

**분류·노출 규칙**:
- 민감 콘텐츠로 분류되면, 사용자가 진입 전 **안내 동의 화면**을 한 번 보게 된다(이후 재노출 없음). 출시 자체는 가능.
- 경미·주의 단계라도 **내부 심의 결과 수위가 높다고 판단되면 출시가 제한될 수 있다.**
- 분류 여부는 출시 검토 시 토스가 판단하며, 분류되면 워크스페이스 멤버에게 메일로 안내된다.

> **건강폰술 적용 메모 (구체 대응은 ③에서 다룸)**:
> 따르기·마시기가 핵심 인터랙션이라 **음주 장면 반복 = 2단계(주의) 분류 가능성**이 있다. 현재 기획 의도는 음주 미화·권장이 아니라 대체·절제이므로, **3단계(출시 불가)로 해석되지 않도록 UX·문구를 제한**한다. 구체적인 연출·문구 대응 원칙은 ③ 앱별 컨텍스트에서 정의한다. → 콘셉트 생존이 걸린 사안이므로 팀 안건·`// REVIEW:` 대상.

## 5. 등록 정보·자산 규격 (어기면 반려)

(출처: 콘솔에서 앱 등록하기 /prepare/console-workspace.md)

### 5.1 변경 불가 값
- **appName: 한 번 등록하면 수정 불가.** `intoss://{appName}` 스킴·인증서 발급 기준. 신중히 결정. → `// REVIEW:` 대상.

### 5.2 노출명 규칙
- **앱 영문명**: 15자 이내, 발음하기 쉬운 명사형. 명령문·동사구 금지. 일반 단어 단독 사용 금지.
- (브런치 반려 사례: 파일 내 앱 이름이 영어로 표기되어 반려 → 한글/영문 표기 규칙 준수 필요)

### 5.3 등록 이미지 규격
- **앱 로고**: 정사각형 600×600 PNG. **배경색 필수(투명 배경 불가).** 토스 제공 리소스 사용·2차 가공 불가.
- **썸네일**: 1932×828 PNG. 빈 공간 색·블러 채움 금지. 토스 리소스 사용·2차 가공 불가.
- **스크린샷(선택)**: 세로 636×1048 / 가로 1504×741 PNG.

### 5.4 앱 유형·연령
- **비게임 분류**: 앱 유형을 "비게임"으로 선택, 카테고리 대/중/소 설정. 게임 분류 시 GRAC 등급분류 의무 발생 → §7 참조.
- **사용 연령**: 앱인토스는 만 19세 이상 대상으로 제공된다(출처: console-workspace.md §4-1③). 출시 전 공식 문서에서 재확인하되, 유지되는 경우 음주 콘텐츠의 미성년 노출 리스크를 낮추는 근거로 활용 가능. → 변동 가능, 출시 전 재확인.

## 6. 어뷰징 방지 (재사용 파이프라인 운용 시 주의)

(출처: /intro/guide.md §3)

- **동일 워크스페이스 내 유사 핵심 기능 앱 반복 출시 금지.** 테마·대상·주제만 바꾼 앱은 별도 앱으로 인정 안 됨.
- 동일 브랜드(이름·로고·색상)로 여러 앱 출시 금지.

> **파이프라인 관점**: 이 파이프라인으로 여러 앱을 찍어낼 때, 같은 워크스페이스에 핵심 기능이 겹치는 앱을 반복 등록하면 반려된다. 새 아이디어는 핵심 기능이 명확히 달라야 별도 앱으로 등록 가능.

## 7. 비게임 앱 분류 리스크

> 건강폰술의 구체적 기술 구현 결정(WebView 선택, SDK 함수 등)은 ③ 앱별 컨텍스트에서 다룬다. 이 절은 **플랫폼이 거는 분류 제약**만 다룬다.

- **게임으로 분류되면 GRAC 등급분류 의무가 발생**한다. 「게임산업진흥법」 제21조에 따라 모든 게임은 게임물관리위원회 등급분류를 받아야 하며, 앱스토어·구글플레이의 IARC 등급은 국내에서 효력이 없다. (출처: /intro/caution.html)
- **리더보드 등 게임센터 기능은 게임 앱 전용**이다. 점수·순위 기능을 넣으면 게임으로 분류될 위험이 있으므로, 비게임 앱에서는 사용 여부를 사전 검토한다. (출처: console-workspace.md §4-2⑥)
- 비게임 유지를 위해, 게임적 요소(점수·랭킹·레벨 등)의 도입 여부는 분류 리스크 관점에서 판단한다. → 구체 배제 결정은 ③에서.
