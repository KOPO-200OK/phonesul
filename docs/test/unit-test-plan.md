## 1. 목적

핵심 계산, 상태 저장, 실시간 건배방 클라이언트 등 독립 가능한 모듈을 빠르고 반복 가능하게 검증한다. 단위 테스트 통과가 토스 WebView, 실제 SDK, 센서, 오디오 또는 별도 실시간 서버의 정상 동작을 보증하지는 않는다.

## 2. 범위

### 2.1 포함

- F-CR-02: 누름 시간에 따른 잔 수위 계산과 상한
- F-CR-03: 탭에 따른 잔 수위 감소
- F-CR-04: 헛누름 8% 경계와 프레임 매핑
- F-MD-01, F-SY-01, F-SY-02: 모드·사운드·진동 설정 저장 및 복원
- F-RT-01, F-RT-03~07: REST 요청 형식, WebSocket 메시지 분기, 재연결 및 종료 처리
- 비게임 정책: `cheers` 메시지에 발신자·횟수·점수·순위 데이터가 포함되지 않음

### 2.2 제외

- 실제 FastAPI/wss 서버와의 통신
- 토스 WebView의 Storage, share, getTossShareLink, 햅틱 및 closeView 동작
- 기기 무음 모드, 백그라운드/복귀 오디오, 모션 센서
- 실제 렌더링 성능·네트워크 지연·메모리 누수
- 사용자 문구·에셋·접근성의 사람 검수

제외 항목은 통합 테스트 또는 대상 환경 수동 테스트로 이관한다.

## 5. 실행 절차

1. `npm ci`로 lockfile 기준 의존성을 준비한다.
2. `npm test`를 실행한다.
3. 실패 시 테스트 ID, 요구사항 ID, 재현 조건, 예상/실제 결과를 기록한다.
4. 기능 결함과 테스트 코드 결함을 구분한 뒤 수정하고 전체 회귀 테스트를 재실행한다.
5. 결과를 `unit-test-result.md`에 반영한다.

## 6. 판정 및 완료 기준

- P0 자동화 케이스 100% 통과
- 실패·스킵·불안정 테스트 0건
- 기능정의서와 테스트 기대값의 불일치 0건
- 발견 결함에 심각도·담당·재검증 상태 기록
- `UNVERIFIED`, `ASSUMPTION`, `REVIEW` 항목을 삭제하지 않고 통합/사람 검수로 이관

## 7. 결함 심각도

| 등급 | 기준 |
|---|---|
| Critical | 앱 실행 불가, 데이터·권한·정책상 출시 불가 |
| Major | P0 핵심 흐름 또는 명세 분기 불충족, 대체 경로 없음 |
| Minor | 우회 가능한 기능 오류, 문구·표현·경미한 호환성 문제 |
| Trivial | 기능 영향 없는 경고·정리 항목 |

## 8. 검수 마커

- `// ASSUMPTION:` 헛누름 8%, 탭당 25%, 속도·재연결 간격 등 임의값은 사람 검수 후 확정한다.
- `// UNVERIFIED:` 토스 SDK, 무음 모드, 센서, 실제 Storage 및 wss 교차 Origin은 이 계획의 단위 테스트로 확정하지 않는다.
- `// REVIEW:` 사용자 노출 문구와 비게임·절주 톤은 자동화 통과 후 사람이 검수한다.

## 9. 사람 검수 게이트 기록

자동화 결과와 별도로 검수자·최종 승인자·검수일·잔여 편차·최종 판정을 결과서에 기록한다. 명세와 구현의 차이는 숨기지 않고 승인 여부와 후속 조치를 함께 남긴다.
