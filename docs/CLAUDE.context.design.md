## 0. 앱 정체성

- **이름(가칭)**: 건강폰술
- **한 줄 정의**: 실제 음주 없이, 폰으로 술을 따르고 건배하는 경험을 시뮬레이션하는 절주·대체형 소셜 WebApp.
- **타깃**: 비음주자, 술자리에서 절주·금주 중인 사람.
- **핵심 가치**: 음주의 **대체·절제**. 실제 음주를 권하지 않으면서 술자리의 분위기·재미만 가져온다.
- **톤**: 가볍고 유쾌하되, 음주를 미화하거나 과음을 부추기지 않는다. (구체 문구 원칙은 §5)

> **콘셉트 한 줄 방어 논리**: "마시는 앱"이 아니라 "안 마시는 사람을 위한 앱". 발표·심사 양쪽에서 이 프레임을 일관되게 유지한다.

## 1. 핵심 기능 (5대)

| # | 기능 | 설명 |
|---|---|---|
| 1 | **음료 선택** | 5종(소주·맥주·와인·막걸리·샴페인) 중 선택. 종류별 병·잔·색·소리·점도 차등 |
| 2 | **길게 눌러 따르기** | 화면을 길게 누르면 잔이 차오름 + 종류별 사운드·햅틱 |
| 3 | **탭해서 비우기** | 잔을 탭하면 실제 음주가 아니라 잔이 비워지는 가상 애니메이션 |
| 4 | **샴페인 흔들기 축하** | 샴페인 한정. 기기를 흔들면 코르크 펑 + 거품 분출 축하 연출(기념·축하 맥락) |
| 5 | **상황 모드** | 혼술 / 술자리 모드 분기 |
| 6 | **건배 공유 + 건강 기록** | 공유 링크로 "건배" 요청 / 실제로 마시지 않은 횟수·절약한 칼로리·비용 표시 |

> 선우님 기능정의서 v0.1과 정렬: 1~4는 코어 인터랙션(F-CR), 5는 모드(F-MD), 6은 건배(F-CH)+기록(F-HL). 검수 필수 기능(F-SY: 사운드·진동 토글, 무음·백그라운드 제어, 종료 모달, 성능)은 §7·§10 참조.

> 기능별 SDK 사용법은 MCP/스킬에 위임한다(②§0). 여기서는 "무엇을 만든다"만 정의한다.

## 2. 화면 흐름

```
진입 → 모드 선택(혼술/술자리) → 음료 선택 → 길게 눌러 따르기 → 탭해서 비우기 → (반복)
                                         └ 샴페인 선택 시 → 흔들어 축하 → 일반 흐름 복귀
                                                                  건배 공유 / 건강 기록
```

따르기·비우기는 화면 전환 없이 한 화면 안에서 대기→따르기→비우기 상태가 순환한다(무한 반복, 비게임 유지). 각 화면의 요소·상태·전환은 화면설계서(선우·현주 담당)에서 확정한다.

> 심사·문서용 표기는 "음료 선택"으로 둔다. 앱 내부 UI 표기는 콘셉트에 맞게 화면설계서에서 조정한다(실제 선택지가 소주·맥주 등이라 UI에선 "술 선택"이 직관적일 수 있음).

## 4. 기술 구현 결정

> SDK 함수의 **상세 사용법은 MCP/스킬에 위임**한다. 여기서는 "무엇을 쓰고 무엇을 안 쓴다"는 결정만 둔다.

- **WebView (React 18 + Vite)** 채택. React Native 아님. (팀 웹 친숙)
- **백엔드 서버 없음** — 순수 정적/CSR.
- **사용 SDK 함수**: Storage, share, getTossShareLink, getAnonymousKey, generateHapticFeedback.
- **Lottie**: RN SDK 불가 → `lottie-web` 사용.
- **오디오 백그라운드**: `onAudioFocusChanged`(RN 전용) 불가 → `visibilitychange`로 처리.
  - 반려 사례 근거: 포그라운드 복귀 시 BGM 미재생 오류로 반려된 사례가 있어, 이 처리는 필수. → `// REVIEW:` 대상(대상 실행 환경에서 동작 확인).

### 4.1 모션 센서 (따르기·흔들기) — 검증 필요

기기 모션은 **앱인토스 SDK가 아니라 웹 표준 브라우저 API**로 접근한다. WebView는 브라우저이므로 `DeviceOrientationEvent`(기울기)·`DeviceMotionEvent`(흔들기/가속도)를 시도할 수 있다.

- **따르기 = 길게 누르기 (기본).** 안정적이고 센서 의존이 없어 폴백으로도 유지한다.
- **기울여 따르기 (선택, 센서 검증 성공 시 추가).** `DeviceOrientationEvent`로 원래 콘셉트(기울여 따르기) 복원 가능. 단 기기·브라우저별 좌표계 편차가 있어 보정 필요.
- **샴페인 흔들기 축하 (F-CR-05).** `DeviceMotionEvent`(셰이크 감지)로 구현. 임계값·쿨다운으로 오작동 방지.

**검증 전 미확정 — `// UNVERIFIED:` 대상 (현승 기술검증):**
1. 앱인토스 WebView(토스앱 내)에서 `deviceorientation` 이벤트가 값을 반환하는가?
2. iOS에서 `DeviceMotionEvent.requestPermission()`(사용자 탭 제스처 내 호출)이 토스 WebView에서 동작하는가? — iOS 13+는 권한 없이는 센서 미작동.
3. `devicemotion`으로 흔들기 감지가 안정적인가? (기기별 편차 확인)

> **설계 안전장치**: 흔들기/기울기가 검증 실패해도 핵심 따르기는 길게 누르기로 동작하도록 폴백을 보장한다. 샴페인 축하는 센서가 안 되면 대체 트리거(예: 길게 눌러 터뜨리기)로 폴백 검토.

## 5. 음주 콘텐츠 UX·문구 대응

> ②§4(민감 콘텐츠 기준, 2단계 분류 가능성)에 대한 건강폰술의 **구체 대응**.

- 음주를 미화·권장하지 않고 **대체·절제** 맥락임을 UX·문구에서 분명히 한다.
- 실제 음주 유도 표현, 과음 연출, 술 권하는 톤을 피한다.
- 술 **브랜드 실명 사용 금지** (특정 상표 광고로 오인 가능).
- 건강 기록(절약한 칼로리·비용)을 통해 "안 마셔서 얻은 것"을 보여주는 방향으로 절제 메시지를 강화한다.
- 민감 콘텐츠로 분류되어 진입 전 안내 동의 화면이 붙는 경우, 그 화면과 앱 콘셉트(대체·절제)의 정합성을 확인한다.

> 위 문구·연출은 사용자에게 그대로 노출되므로 "AI 생성 흔적·UX 자연성" 검수 대상이다(①§7). → `// REVIEW:` 대상.

### 5.1 문구 가이드 (금지 → 대체)

| 금지 표현 | 대체 표현 |
|---|---|
| 한 잔 더 마셔볼까요? | 한 번 더 가상 건배해볼까요? |
| 원샷! | 가볍게 비워볼까요? |
| 취할수록 재밌어요 | 실제 음주 없이 분위기만 즐겨요 |
| 술이 부족해요 | 다른 조합도 둘러볼까요? |
| 오늘 제대로 마셔요 | 오늘은 마시지 않고 분위기만 즐겨요 |

> Claude Code가 UI 문구를 생성할 때 이 표를 기준으로 삼는다. 음주 권장 톤과 AI 생성 문구 실수를 동시에 줄인다.

## 6. 비게임 유지 결정

> 플랫폼 분류 리스크 근거는 ②§7. 여기서는 건강폰술의 **구체 배제 결정**.

- **점수·랭킹·레벨·리더보드 배제.** 게임으로 분류되면 GRAC 등급분류 의무가 생기므로, 비게임 유지를 위해 게임적 경쟁 요소를 넣지 않는다.
- "건배 공유"는 경쟁·순위가 아니라 소셜 상호작용(함께 건배)으로 설계한다.
- **샴페인 흔들기(F-CR-05)는 축하 연출이지 게임 메커닉이 아니다.** 점수·성공/실패·목표가 없는 1회성 연출로 설계해 게임성 오인을 피한다. 따르기·비우기도 목표·엔딩 없는 무한 반복으로 유지(F-CR-04).

## 7. 검수 필수 기능 · 비기능 요구사항

> 선우님 기능정의서 F-SY 및 비기능 요구사항 반영. 앱인토스 검수 통과에 필수.

### 7.1 검수 필수 기능 (F-SY)
- **사운드 On/Off**(F-SY-01), **진동 On/Off**(F-SY-02) — 설정은 재진입 후에도 유지. 진동을 꺼도 시각·청각 피드백은 유지(접근성: 단일 감각 의존 금지).
- **무음 모드 존중**(F-SY-03) — 기기 무음 시 사운드 자동 억제. 사용자 설정이 아닌 시스템 자동 동작.
- **백그라운드 사운드 제어**(F-SY-04) — 백그라운드 전환 시 즉시 정지, 복귀 시 재생. `visibilitychange`로 처리(§4 참조). 시스템 자동 동작.
- **종료 확인 모달**(F-SY-05) — 종료 시 확인 모달로 실수 종료 방지.
- **닫기 버튼**(F-SY-06) — 우측 상단 닫기(X) 모든 주요 화면에서 정상 동작.

### 7.2 성능 기준
- **초기 로딩 10초 이내**(F-SY-07) — 필수 에셋 우선 로드. 미달 시 검수 탈락 위험.
- **인터랙션 반응 2초 이내**(F-SY-08) — 에셋 사전 로드로 즉시 피드백. 미달 시 검수 탈락 위험.

### 7.3 인터랙션 구현 디테일
- **헛누름 분기**(F-CR-04) — 따르다가 손 떼는 시점의 잔 수위가 임계값(예: 8%) 미만이면 마시기로 가지 않고 대기로 복귀. 임계값은 검수 단계에서 조정 가능. → `// ASSUMPTION:` 대상(8%는 임의값).
- **상태 순환** — 따르기·비우기는 화면 전환 없이 한 라우트에서 요소 등장/퇴장(페이드)으로 처리해 끊김 최소화.
- **안정성** — 상태 전환 반복 시 메모리·사운드 누수 없이 동작.

## 9. 자산 (미정·후보)

> "단계가 요구하면 쓰고 아니면 줄인다"(①§1.3). 자산 필요 여부 자체가 일부 미정.

- **일러스트**: 현주 선별 1차 + 부족분만 이미지 AI 보강. 5종 스타일 **일관성 검수 필요**(섞이면 AI 생성 흔적으로 보임). → `// REVIEW:` 대상.
- **사운드**: 효과음 필요 여부 **팀 미정**. 생성한다면 ElevenLabs Sound Effects 또는 CC0 음원 라이브러리를 후보로 둔다. 실제 적용 전 사용 플랜, 상업적 사용 가능 여부, 앱 내 사용 범위, 독립 파일 배포 제한 여부를 확인한다. → `// UNVERIFIED:` 대상.
- **생성형 AI 고지·표시 의무**: 정적 자산(미리 만든 효과음·그림)에 ②§3 의무가 적용되는지 출시 전 확인. → `// UNVERIFIED:` 대상.
