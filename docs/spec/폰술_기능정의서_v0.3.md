## 1. 프로젝트 개요

### 1.1 서비스 정의
마시지 않고 마시는 기분만 내는 음주 대체 인터랙션 앱이다. 술을 고르고, 화면을 길게 눌러 따르고, 탭해서 마시는 연출을 사실적인 애니메이션·사운드·진동으로 제공한다. 실제 음주가 아니라 음주의 '분위기'와 '동작'만을 대체 경험으로 제공한다.

### 1.2 타깃 사용자
- 금주·절주 중인데 음주 분위기가 그립거나 욕구가 올라오는 사람
- 술자리에서 술을 안 마시지만 어색하지 않게 잔을 들고 싶은 사람 — 비음주자, 운전자, 임산부, 건강·종교상 이유 등
- 기념일·축하 자리에서 술 없이 분위기를 즐기고 싶은 사람

### 1.3 컨셉 톤 (정책 방어 핵심)
- 음주를 미화·조장하지 않는다. "마시지 않고도 분위기를 즐긴다"는 대체·절제의 긍정 메시지를 일관되게 유지한다.
- 기록·점수·보상 같은 장치 없이 동작과 분위기 자체로 만족을 주어 '덜 마시는 선택'을 돕는다.
- 이 톤은 사용자 보호와 앱인토스 음주 조장 검수 양쪽에서 방어막으로 작동한다.

### 1.4 핵심 차별점
- 따르기·마시기를 한 화면 안의 상태 전환으로 처리해 끊김 없는 무한 반복 루프 제공
- 술 종류별 사실적 연출(병·잔 모양·색·소리·점도 차등)
- 샴페인 '흔들어 터뜨리는' 축하 연출 — 기념·축하 맥락 전용 경험
- 실시간 건배방으로 여러 명이 동시에 "짠" — 경쟁·집계 없는 동시 축하

### 1.5 프로젝트 성격
게임이 아니라 '앱을 만들어내는 자동화 시스템(하네스)' 구축이 본질이다. Claude Code 하네스에 단계별 사람 검수 게이트를 결합해 진행하며, 각 단계 산출물을 담당자가 검수·승인한 뒤 다음 단계로 넘어간다. 본 문서는 그 검수 게이트의 입력 산출물이다.

## 2. 기능 구조 및 ID 체계

### 2.1 기능 분류
1차 MVP 기능은 다음 4개 영역으로 분류한다.

| 코드 | 영역 | 설명 |
|---|---|---|
| CR | 코어 인터랙션 | 술 선택·따르기·마시기·상태 순환·샴페인 축하 연출 |
| MD | 상황 모드 | 혼술 / 술자리 맥락별 분위기 분기 |
| RT | 실시간 건배방 | 방 생성·코드 공유·참여·인원 동기화·실시간 짠·종료/만료 (별도 백엔드 wss) |
| SY | 검수 필수 기능 | 앱인토스 정책 통과를 위한 시스템·설정 요구 |

> v0.2의 링크 매개 비동기 건배(F-CH)는 **제거**되고 RT로 대체되었다.

### 2.2 ID 체계
기능 ID는 `F-{영역코드}-{일련번호}` 형식을 사용한다. 예) `F-CR-05` = 코어 인터랙션 영역의 5번 기능(샴페인 축하 연출).

### 2.3 우선순위 정의
- **필수** — 1차 MVP 출시 및 검수 통과에 반드시 포함되는 기능.
- **권장** — 품질을 높이나 미포함 시에도 출시 가능.
- **후순위** — 2차 이후 검토(예: 다중 서버 인스턴스 확장, 술 종류 확장 등).

## 4. 상세 기능 정의

### 4.A 코어 인터랙션 (CR)
따르기·마시기는 화면을 바꾸지 않고 한 화면 안에서 '대기(병만) → 따르기(병+줄기+잔) → 마시기(잔만) → 비움 → 대기' 상태로 순환한다. 소주·맥주·와인·막걸리는 동일한 따르기/마시기 엔진을 공유하며 병·잔 모양·색·소리·점도만 다르다. 샴페인은 동일 엔진에 '흔들어 터뜨리는' 축하 연출(F-CR-05)이 추가된다.

**F-CR-01 · 술 종류 선택**
- 설명: 마실(연출할) 술을 이미지로 선택한다. MVP 5종: 소주·맥주·와인·막걸리·샴페인. 종류별로 병·잔 모양, 액체 색, 소리, 점도(차오르는 속도/질감)를 차등 적용한다. 소주·맥주·와인·막걸리는 따르기/마시기 동작이 동일하고 외형·연출만 다르며, 샴페인은 여기에 축하 연출이 더해진다.
- 트리거: 술 카드(이미지) 탭
- 처리: 선택 술을 세션에 저장하고 종류별 병·잔·색·소리·점도 프리셋과 (샴페인은 축하 연출 프리셋까지) 에셋을 로드한다.
- 출력: 선택 술 기준의 '대기(병만)' 상태 화면 진입
- 정책: 술 브랜드 실명·로고 미사용, 가상 일반명칭만 사용(상표·광고 위험 회피).

**F-CR-02 · 따르기 (대기 → 따르기)**
- 설명: 대기 상태에서는 화면에 병만 보인다. 화면을 길게 누르면 병이 기울며 줄기가 흐르고, 줄기가 닿는 잔이 등장해 차오른다. 누르는 시간으로 양을 조절하고 손을 떼면 멈춘다. 종류별 소리·햅틱이 동반된다.
- 트리거: 화면 롱프레스(누름 지속 시간)
- 처리: 누름 지속 시간을 잔의 차오름(0~100%)에 매핑. 가득 차면 상한에서 멈춤(넘침 없음). 떼면 즉시 정지하고 마시기 분기 판단(F-CR-04)으로.
- 출력: 병 기울기 + 줄기 흐름 + 잔 차오름 애니메이션 + 종류별 사운드·햅틱(설정 종속)
- 정책: 폭음·과음 부추기는 연출(끝없이 넘침 등) 지양. 병은 소진되는 자원이 아니라 따르기 도구로만 다룸(빈 병 상태 없음).

**F-CR-03 · 마시기 (따르기 → 마시기)**
- 설명: 따르기에서 손을 떼면 병·줄기가 사라지고 잔만 중앙에 남는다. 잔을 탭하면 꿀꺽 소리·진동과 함께 줄어들고, 다 비우면 "캬~" 효과음과 빈 잔이 된다.
- 트리거: 잔 영역 탭(반복)
- 처리: 탭마다 일정량 감소, 0이 되면 비움 완료로 전환.
- 출력: 꿀꺽 사운드·진동, 액체 감소, 비움 시 "캬~" + 빈 잔
- 정책: 음용량·취함 정도 수치화·경쟁 요소 금지. 단순 연출에 한정.

**F-CR-04 · 상태 순환 · 다시 따르기**
- 설명: 비움 완료 후 다시 '대기(병만)' 상태로 돌아가 무한 반복한다. 따르다가 거의 안 따르고 손을 뗀 경우(헛누름)에는 마시기로 가지 않고 대기로 복귀한다. 목표·점수·엔딩이 없는 무한 반복으로 비게임 성격을 유지한다.
- 트리거: 비움 완료 / 따르기 종료(손 떼기)
- 처리: 손 떼는 시점의 잔 수위가 임계값(예: 8%) 이상이면 마시기로, 미만이면 대기로 복귀. 비움 완료 시 잔 초기화 후 대기 전환.
- 출력: 대기(병만) 상태로 복귀 → 따르기 가능
- 정책: 엔딩·클리어·스테이지 등 진행 구조 없음(게임 분류 회피). 임계값은 검수 단계에서 조정 가능.

**F-CR-05 · 샴페인 축하 연출**
- 설명: 샴페인을 선택했을 때만 활성화되는 특수 연출. 기기를 흔들면 코르크가 '펑' 터지며 거품이 분출하는 축하 연출(소리·진동·시각)이 재생된다. 기념일·축하 자리에서 술 없이 분위기를 내는 용도다.
- 트리거: 샴페인 선택 상태에서 기기 흔들기(셰이크 감지)
- 처리: 셰이크 임계값을 넘으면 코르크 펑 + 거품 분출 연출 1회 재생, 이후 일반 따르기/마시기 흐름으로. 흔들기 외 동작은 다른 술과 동일.
- 출력: 코르크 펑 효과음·강한 햅틱 + 거품 분출 축하 애니메이션
- 정책: 축하 맥락에 한정하며 폭발·폭음 미화로 읽힐 과격한 표현 지양. 진동·사운드는 설정·무음 모드 종속.

### 4.B 상황 모드 (MD)

**F-MD-01 · 모드 선택**
- 설명: 첫 화면에서 혼술 모드와 술자리 모드 중 하나를 선택. 이후 설정에서 전환 가능.
- 트리거: 모드 카드 탭 / 모드 토글
- 처리: 선택 모드를 세션에 적용하고 해당 모드의 BGM·배경·연출 속도 프리셋 로드.
- 출력: 선택 모드 기준의 술 선택 화면 진입

**F-MD-02 · 혼술 모드**
- 설명: 혼자 차분히 음미하는 맥락. 잔잔한 BGM, 차분한 배경, 천천히 음미하는 톤.
- 처리: 느린 연출 속도, 차분한 BGM·배경 프리셋 적용

**F-MD-03 · 술자리 모드**
- 설명: 여럿이 어울리는 맥락. 빠른 원샷 연출과 활기찬 분위기.
- 처리: 빠른 연출 속도, 활기찬 BGM·배경 프리셋 적용
- 정책: 분위기 연출에 한정하며 폭음·원샷 강요로 읽힐 표현 지양.

### 4.C 실시간 건배방 (RT)
기존 '링크 매개 비동기 건배(F-CH)'는 **제거**되었다. 대신 별도 백엔드 서버(FastAPI + WebSocket)에 연결되는 실시간 건배방을 제공한다. 주최자가 방을 만들어 코드를 공유하고, 참여자가 코드로 입장하면 방 안 누구나 '짠'을 보내 전원이 동시에 축하 연출을 본다. 서버 규약·운영 파라미터는 §10을, 사람 확인이 필요한 지점은 §11을 참조한다.

**F-RT-01 · 방 생성**
- 설명: 주최자가 건배방을 생성. 서버가 방과 6자리 코드(혼동문자 0·O·1·I 제외), 방장 토큰을 발급.
- 트리거: '건배방 만들기' 선택 (서버 `POST /rooms`)
- 처리: 서버가 Room 생성 + 고유 코드 발급(충돌·폐기 코드 회피) + 방장 토큰(host token) 부여. 생성자에게만 1회 반환하며 영속 저장하지 않음(휘발).
- 출력: 방 코드 표시 + 공유 진입. 응답: `{ code, hostToken }`
- 정책: 코드 추측 남용 방지(시도 제한·만료). 코드 길이·문자셋은 임의값(서버 기준, §11 ASSUMPTION).

**F-RT-02 · 코드 공유**
- 설명: 발급된 방 코드를 참여자에게 전달. 코드를 화면에 노출하거나 앱인토스 share로 전달(과거의 '건배 링크'가 아니라 방 입장 코드).
- 처리: 방 코드 문자열을 표시하거나 공유 시트로 전달
- 정책: 개인정보·실명 식별값을 담지 않음(코드만).

**F-RT-03 · 방 참여**
- 설명: 참여자가 코드를 입력하면 wss로 방에 연결되어 입장. 연결 자체가 참여이며, 서버 발급 익명 식별자만으로 멤버 등록.
- 트리거: 코드 입력 후 '참여' (`wss /ws/{room_code}` 연결)
- 처리: Origin 검사 → 시도 제한 확인 → 코드 검증(없음·만료 거절) → 정원 검사 → 익명 멤버(memberId·socketId) 등록 → roster 브로드캐스트.
- 출력: 방 화면 진입, 현재 인원 표시
- 정책: 익명 참여(실명·연락처·토스 식별값 저장 금지). 로그인 강제 여부는 검수 확인(§11 REVIEW).

**F-RT-04 · 인원 동기화**
- 설명: 입장·퇴장이 일어날 때마다 방 인원수와 멤버 목록(roster)을 방 전원에게 실시간 갱신.
- 처리: roster 메시지(인원수 count, 서버 발급 memberId 목록)를 같은 방 전원에게 broadcast.
- 정책: 실명·연락처 없이 서버 발급 memberId만 노출.

**F-RT-05 · 실시간 짠 (핵심)**
- 설명: 방 안 누구나 '짠' 버튼을 누르면, 같은 방 전원 화면에 동시에 짠 연출(잔 부딪힘 + 소리·진동)이 재생.
- 트리거: '짠' 버튼 (wss `cheers` 메시지)
- 처리: 서버가 cheers를 받아 같은 방 전원에게 1회씩 broadcast. 멤버별 쿨다운으로 연타를 디바운스(쿨다운 내 후속 짠은 조용히 드롭). 봉투에 보낸 사람·횟수 없음.
- 출력: 전원 동시 '짠' 연출(소리·진동은 F-SY 설정·무음 모드 종속)
- 정책(중요): **비게임 — 누가 먼저/많이 짠 표시·집계·순위 금지**(구조적으로 sender·count 미포함). 체감 지연 최소화(수백 ms 목표).

**F-RT-06 · 방 종료·만료**
- 설명: 방장이 방을 종료하거나 일정 시간 유휴 상태가 지속되면 방과 상태를 폐기. 폐기된 코드는 재사용하지 않음.
- 트리거: 방장 종료(`POST /rooms/{code}/close`, 방장 토큰) 또는 유휴 만료
- 처리: 전원에 room_closed(사유: host_ended | expired) 안내 → 소켓 종료 → 방·멤버 폐기 → 코드 재사용 금지 등록. 만료는 주기적 sweep으로 정리.
- 정책: 방 없음·토큰 불일치를 동일 404로 응답(존재·토큰 추측 단서 최소화).

**F-RT-07 · 재연결 (권장)**
- 설명: 소켓이 끊겼을 때 같은 코드로 다시 연결하면 재입장으로 처리되고 인원 상태(roster)가 복구.
- 처리: 재연결 시 멤버 재등록 후 roster 재전송으로 상태 복구. 멤버 식별자를 유지하는 identity-resume는 범위 외(1차는 익명 재입장).
- 정책: 백그라운드 전환 시 소켓·사운드 처리는 프론트 F-SY-04와 연계(§11 REVIEW).

### 4.D 검수 필수 기능 (SY, 앱인토스 정책)
앱인토스 정책 통과를 위해 반드시 충족해야 하는 시스템·설정 요구사항이다.

- **F-SY-01 · 사운드 On/Off** — 사운드 재생 여부 설정. 설정은 재진입 후에도 유지.
- **F-SY-02 · 진동 On/Off** — 진동(햅틱) 여부 설정. 꺼도 시각·청각 피드백 유지. 접근성: 단일 감각 의존 금지.
- **F-SY-03 · 무음 모드 존중** — 기기 무음 모드 시 사운드 자동 억제. OS 미디어·무음 정책 준수.
- **F-SY-04 · 백그라운드 사운드 제어** — 백그라운드 전환 시 사운드 즉시 정지, 복귀 시 재생. 백그라운드 음원 무단 재생 금지.
- **F-SY-05 · 종료 확인 모달** — 종료 동작(닫기/뒤로) 시 확인 모달 노출. 실수 종료 방지.
- **F-SY-06 · 닫기 버튼** — 우측 상단 닫기(X)가 주요 화면에서 정상 동작.
- **F-SY-07 · 초기 로딩 성능** — 최초 진입 시 첫 화면 10초 이내 로딩. 미달 시 검수 탈락 위험.
- **F-SY-08 · 반응 성능** — 주요 인터랙션 반응 2초 이내(에셋 사전 로드). 미달 시 검수 탈락 위험.

## 9. 정책·컴플라이언스 체크리스트
검수 게이트에서 점검할 항목이다.

- [ ] 음주 미화·조장 표현 없음 / "대체·절제" 메시지 유지 (1.3)
- [ ] 게임 요소(점수·레벨·랭킹·엔딩) 없음 — 상태 순환 무한 반복 유지 (F-CR-04, §5)
- [ ] 병 소진/자원 관리 없음 — 빈 병 상태 없음 (§5)
- [ ] 현금성 보상·사행성 요소 없음 (§5)
- [ ] 술 브랜드 실명·로고 미사용 / 가상 일반명칭만 사용 (F-CR-01)
- [ ] 샴페인 축하 연출이 폭발·폭음 미화로 읽히지 않도록 표현 점검 (F-CR-05)
- [ ] 사운드·진동 설정 제공, 무음·백그라운드 정책 준수 (F-SY-01~04)
- [ ] 종료 확인 모달 및 닫기 버튼 정상 동작 (F-SY-05/06)
- [ ] 초기 로딩 10초·반응 2초 성능 기준 충족 (F-SY-07/08)
- [ ] 실시간 짠이 비게임 — 보낸 사람·횟수·순위 미표시·미집계 (F-RT-05)
- [ ] 건배방 익명·휘발 — 실명·연락처·토스 식별값 미저장, 방 종료 시 폐기 (§7)
- [ ] 코드 추측 남용 방지(시도 제한) 및 방 존재·토큰 단서 최소화 (F-RT-01/06)
- [ ] wss 끊김·실패 시 음주 조장 톤 없는 에러 안내 (F-RT, §10)
- [ ] 검수 확인 지점(UNVERIFIED·ASSUMPTION·REVIEW) 사람 확인 완료 (§11)

## 10. 백엔드 서버 규약 (실시간 건배방)
실시간 건배방은 앱인토스 미니앱(프론트)과 분리된 별도 FastAPI 서버로 동작한다. 방 생성·종료는 REST, 참여·인원·짠은 WebSocket(wss)을 사용한다. 앱인토스 API 규약(mTLS·QPM)과는 분리된 내부 통신이다.

### 10.1 엔드포인트
| 엔드포인트 | 메서드 | 설명 |
|---|---|---|
| `/health` | GET | 헬스체크 → `{ status: "ok" }` |
| `/rooms` | POST | 방 생성(F-RT-01) → `{ code, hostToken }` (201) |
| `/rooms/{code}/close` | POST | 방장 종료(F-RT-06). 헤더 `X-Host-Token` 검증. 불일치·없음은 404 |
| `/ws/{room_code}` | WS | 방 참여·인원 동기화·짠(F-RT-03/04/05). 연결=참여 |

### 10.2 메시지 타입 (wss, JSON)
| 방향 | type | 설명 |
|---|---|---|
| C→S | join | 코드로 방 참여(F-RT-03). 연결 수립이 곧 참여 |
| C→S | cheers | '짠' 전송(F-RT-05) |
| C→S | leave | 방 퇴장(F-RT-04). 소켓 종료로도 처리 |
| S→C | roster | 인원수·멤버 목록 동기화(F-RT-04) |
| S→C | cheers | 전원 동시 '짠' 브로드캐스트(보낸 사람·횟수 없음) |
| S→C | room_closed | 방 종료·만료 안내(reason: host_ended | expired) |
| S→C | error | 에러 안내(음주 조장 톤 금지). 예: invalid_code, room_full, too_many_attempts |

### 10.3 운영 파라미터 (현재 기본값 · 검수에서 확정)
| 항목 | 기본값 | 비고 |
|---|---|---|
| 방 코드 | 6자 | 영문 대문자+숫자, 혼동문자(0·O·1·I) 제외 |
| 유휴 만료 | 30분 | 마지막 활동 이후. 주기 sweep(30초)으로 정리 |
| 짠 연타 쿨다운 | 1000 ms | 멤버별 디바운스. 쿨다운 내 후속 짠은 드롭 |
| 방 정원 | 50명 | 초과 입장 거절(room_full) |
| 코드 시도 제한 | 60초당 10회 | 초과 시 차단(코드 추측 남용 방지) |

> 위 기본값은 서버 구현의 임의 초기값(ASSUMPTION)으로, 검수 단계에서 운영 정책으로 확정한다.

백엔드 구현에 표시된 검수 마커다. 하네스 입력 전 사람이 확인·확정해야 하는 지점이다.

|---|---|
| UNVERIFIED | 토스 WebView가 보내는 Origin 값 미확인 — 현재 CORS는 전체 허용(*). 출시 전 실제 Origin으로 좁혀야 함 |
| REVIEW | 미니앱 WebView ↔ 자체 서버 wss 사용 가능 여부(운영자 채널톡 확인 2026-06-22). 정책 개정 가능성 있어 출시 전 재확인 |
| REVIEW | 로그인 강제 여부 — 현재 방장 토큰만으로 권한 구분(토스 로그인 비강제) |

## 12. 화면설계서 연동 개정 포인트
본 개정(링크 공유 제거 · 실시간 건배방 추가)에 맞춰 화면설계서도 다음과 같이 개정한다.

| 화면 | 변경 |
|---|---|
| S-06 (기존 건배 요청) | 링크 공유 화면 제거 → '건배방 만들기 / 코드로 참여' 진입으로 변경 |
| S-07 (기존 건배 수신) | 비동기 링크 수신 제거 → 실시간 건배방 화면(인원·짠 버튼·전원 짠 연출)로 변경 |
| 신규 건배방 화면 | 방 코드·인원 목록·짠 버튼·연결 상태(끊김/재연결) 표시 |
