# 폰술 기능정의서 v0.3 (프론트)

**음주 대체 인터랙션 앱 · 실시간 건배방 추가**
앱인토스(Toss 미니앱) 기준 · 프론트엔드 관점

| 항목 | 내용 |
|---|---|
| 문서명 | 폰술 기능정의서 (프론트) |
| 버전 | **v0.3 (실시간 건배방 추가)** |
| 이전 | v0.2 (기록 기능 제거) |
| 플랫폼 | 앱인토스 (Toss 미니앱) + 별도 서버 레포(phonesul-server, FastAPI+wss) |
| 대상 범위 | v0.2 전체 + **실시간 건배방(RT)** 1차 편입 |
| 핵심 구조 | 따르기·마시기 무한 반복 + **코드 기반 실시간 다중 건배** |

| 컨셉 원칙 | 음주 미화·조장 금지 / 대체·절제 메시지 / **건배는 경쟁 아닌 동시 축하** |

## 2. 기능 구조 및 ID 체계

### 2.1 기능 분류 (영역)

| 코드 | 영역 | 설명 |
|---|---|---|
| CR | 코어 인터랙션 | 술 선택·따르기·마시기·상태 순환·샴페인 축하 (v0.2 유지) |
| MD | 상황 모드 | 혼술 / 술자리 분기 (v0.2 유지) |
| CH | 건배 요청 | 공유 링크 비동기 ‘짠’ (v0.3에서 실시간 경로 연계) |
| SY | 검수 필수 기능 | 앱인토스 정책 통과 시스템·설정 (v0.2 유지) |
| **RT** | **실시간 건배방** | **방 생성·코드 참여·실시간 짠·인원 동기화 (v0.3 신규)** |

### 2.2 ID 체계
F-{영역코드}-{일련번호}. 예) F-RT-05 = 실시간 건배방 5번(실시간 짠).

### 2.3 우선순위
- 필수 — 1차 출시·검수 통과에 반드시 포함.
- 권장 — 품질 향상, 미포함도 출시 가능.
- 후순위 — 2차 이후(다중 서버 인스턴스, 방 채팅 등).

## 4. 상세 정의 (프론트 관점)

### F-RT-01 · 방 생성
- **트리거:** S-06에서 “건배방 만들기”.
- **프론트 동작:** `POST /rooms` 호출 → 방 코드 + 방장 토큰 수신 → 그 코드로 wss(`/ws/{코드}`) 연결 → 방장으로 입장 → S-10 진입.
- **출력:** 방 코드 표시 + 공유 버튼.
- **정책:** 코드는 사용자 노출 → 표기 자연스럽게. 서버 주소 하드코딩 금지 → `// REVIEW(서버 endpoint 설정):`.

### F-RT-03 · 방 참여
- **트리거:** S-06에서 “코드로 참여” → 코드 입력.
- **프론트 동작:** `ws://.../ws/{코드}` 연결 → join 송신 → roster 수신 → S-10 진입. 잘못된/만료 코드 → error 안내.
- **정책:** 익명 참여(로그인 미사용 확정). 실명·연락처 입력 없음.

### F-RT-05 · 실시간 짠 (핵심)
- **트리거:** S-10에서 “짠” 버튼(방 안 누구나).
- **프론트 동작:** cheers 송신 → 서버 broadcast된 cheers 수신 시 **전원 동시 짠 연출**(기존 잔 부딪힘 연출 재사용).
- **연동:** 짠 연출의 사운드·진동은 설정·무음 모드에 종속(F-SY-01/02/03 승계). 진동 꺼도 시각 피드백 유지.
- **비기능:** 체감 지연 최소(목표 수백 ms) → `// REVIEW(실측):`. 연타 시 과도 연출 방지(서버 쿨다운과 정합).
- **정책(중요):** 누가 먼저/많이 짰는지 **집계·순위·표시 금지**(비게임, 정책 핵심). 짠은 동시 축하일 뿐.

### F-CH-03(개정) · 건배 수신·연출
- 방에 입장해 있으면 실시간(F-RT-05) 우선. 방 밖이면 기존 비동기 링크 수신 연출 폴백 유지.

## 5. 화면 정의 (프론트 보강 — 화면설계서 v0.3 연동)

### S-10 건배방 (신규)
방에 입장한 상태의 메인 화면.

| 영역 | 구성요소 | 비고 |
|---|---|---|
| 상단 | 방 코드 표시 + 공유 버튼 | 방장·참여자 공통. 코드 복사/share |
| 중앙 | 참여 인원 목록·인원수 | roster 수신으로 실시간 갱신. 익명 표기(닉/번호) |
| 중앙 | 내 잔 + 짠 연출 영역 | 기존 잔 에셋 재사용. cheers 수신 시 전원 동시 연출 |
| 하단 | “짠” 버튼 | 누구나 누름. 연타 쿨다운 |
| 상태 | 연결 상태 표시(연결중/끊김/재연결) | 끊김 시 안내 + 재연결 |
| 종료 | 나가기 / (방장)방 종료 | F-RT-06. 종료 확인(F-SY-05 승계) |

> 짠 연출은 새로 만들지 않고 **기존 따르기/마시기의 잔 연출을 재사용**한다(일관성, 에셋 추가 최소화).

### S-06 건배 요청 (개정)
- 기존: 혼자 공유 링크 생성.
- 추가: **“건배방 만들기”**(→ F-RT-01), **“코드로 참여”**(→ F-RT-03) 진입 버튼.

### S-07 건배 수신 (개정)
- 기존: 비동기 링크 수신 → 짠 연출.
- 추가: 실시간 방 경로(S-10) 안내. 두 경로 공존(F-CH-03).

## 6. 검수 필수(SY) 승계 + 실시간 추가 고려

- F-SY-01~08(사운드·진동·무음·백그라운드·종료모달·닫기·로딩·반응) **v0.2 그대로 유지**.
- 추가 고려:
  - wss 연결 끊김/실패 시 사용자 안내(에러 상태) — UX 누락 없게.
  - 백그라운드 전환 시 **소켓·사운드 동시 처리**(F-SY-04 연계) → `// REVIEW(백그라운드 소켓 처리):`.
  - S-10도 닫기 버튼(F-SY-06)·종료 확인(F-SY-05) 적용.

## 7. 정책·컨셉 대응 (v0.2 승계 + 실시간 보강)

- 음주 미화·조장 금지. 건배방 문구도 문구 가이드(금지→대체) 준수.
- **비게임 유지:** 짠 횟수·순위·리더보드 절대 없음. 방은 경쟁이 아니라 함께 축하.
- 술 브랜드 실명 금지(방 이름·문구 포함).
- 익명·휘발: 프론트는 개인정보 입력 없이 코드로만 참여. 서버도 영속 저장 안 함(서버 문서 정합).
- 외부 통신: 우리 서버(phonesul-server)와의 데이터 통신. 외부 웹페이지 랜딩 아님(앱인토스 외부링크 제한 정합).

---

## 8. 범위 밖 (후순위)

- 다중 서버 인스턴스 확장(Redis pub/sub 등) — 1차 단일 인스턴스.
- 방 내 채팅·음성·이모지 — 범위 외.
- 짠 통계·기록 — 비게임·기록 제거 방침상 범위 외.
